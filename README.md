# Личный гардероб

Четыре раздела: «Мои вещи», «Вдохновение», «Образы», «Хочу купить». Светлый адаптивный интерфейс с мягким откликом карточек. На компьютере меню слева, на телефоне снизу.

Сайт: https://zaretsky123.github.io/wardrobe/. Исходный код: https://github.com/zaretsky123/wardrobe.

## Возможности первой версии

- Несколько фото каждой вещи, тип фото, подпись, порядок, выбор обложки.
- Фото на устройстве уменьшаются до 2400 px по длинной стороне; JPEG перекодируется без исходных EXIF-метаданных. Некоторые HEIC-файлы требуют конвертации или скриншота, если браузер не умеет их читать.
- Поиск, категории, сезоны, избранное, сортировка.
- Готовые образы со связанными карточками вещей; при отсутствии общего фото — коллаж вещей.
- Связь образа с референсом и перенос купленной вещи в гардероб.
- Корзина и восстановление. Вещь, используемую в образах, нельзя удалить навсегда, пока связи не удалены.
- ZIP-экспорт всех карточек, связей и оригиналов сохранённых фото. Самостоятельный импорт архивов в интерфейсе пока не реализован; архив пригоден для восстановления административным скриптом.

## Локальный запуск

Node.js 24. Установка: `npm ci --ignore-scripts`. Проверки: `npm test`. Сборка: `npm run build`. Просмотр: `npm run serve` (http://localhost:4173).

Для рабочего подключения задаются `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY` при сборке либо в `public/config.json`. Оба значения публичные. Секретные ключи, пароль пользователя, фотографии и данные гардероба в GitHub не хранятся.

## Supabase

Используется отдельный проект `wardrobe` (`bzeelpupjsmlqtkcmzsi`) в организации Artuz на Free. `supabase/schema.sql` — воспроизводимый снимок схемы для чистого проекта. Схема применена через миграции Supabase; три Edge Functions развёрнуты. Все таблицы имеют RLS и явные grants. `wardrobe_access` разрешает ровно один аккаунт, клиент не может добавить себя в список.

Фото находятся в приватном bucket `wardrobe`. Авторизованный клиент получает временные ссылки, обновляемые во время использования. В браузере хранится только сессия входа, а не гардероб. Выход отзывает refresh-токены; ранее выданные ссылки работают до истечения срока (до 15 минут), даже после выхода.

Edge Function `wardrobe-login` принимает логин и пароль, на сервере сопоставляет логин с единственным владельцем и проверяет пароль через Supabase Auth. Открытая регистрация и anonymous sign-in выключены в настройках проекта; состояние проверено через Auth API.

Для первого аккаунта используется одноразовая закрытая ссылка, обслуживаемая `wardrobe-setup`. Пользователь сам выбирает логин, email и пароль. Единственный токен настройки создаётся администратором; публичной регистрации нет. Повторный запуск настройки требует нового токена, созданного администратором. При настройке входа endpoint без платформенной проверки JWT использует собственную аутентификацию.

## Доступ помощника к фотографиям

Подключение Supabase читает карточки и связи через SQL. Чтобы скачать приватные фото без передачи пароля владельца, администратор создаёт одноразовый 32-байтовый случайный токен, хранит только его SHA-256 в `wardrobe_agent_tickets` с TTL 5 минут. `wardrobe-agent` атомарно расходует его и возвращает каталог с временными ссылками на изображения. Клиентские роли не имеют доступа к билетам; endpoint проверяет наличие владельца. Отказ запросу без токена проверен на развёрнутой функции; повторное использование проверено локальным тестом. Проверку с фотографиями владельца можно выполнить после создания его аккаунта.

Токены и подписанные URL никогда не коммитятся и не записываются в публичные логи. Запись образов помощником выполняется через подключение к базе по запросу пользователя с сохранением `user_id` и отношений.

## GitHub Pages

Подготовлен workflow `.github/workflows/pages.yml`. После создания репозитория в Settings → Pages выбирается GitHub Actions. Переменные `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY` можно задать в Actions variables; их также допустимо хранить в `public/config.json`.

GitHub Pages отдаёт публичную оболочку приложения. Данные и фотографии защищены Supabase на сервере, не только экраном входа. Для приватного репозитория доступность Pages зависит от тарифного плана; размещение выбирается при запуске.

## Первое использование

1. Владелец сам задаёт логин, email и пароль по отдельной одноразовой ссылке. Токен ссылки в репозитории не хранится.
2. После входа добавить первую вещь и проверить фото, сохранение, выход и повторный вход. До создания владельца такие проверки с настоящими личными данными не выполнены.

Проверки и их границы описаны в `VALIDATION.md`. Проверки таблиц не выявили проблем с доступом или RLS. Auth advisor отмечает отключённую проверку утёкших паролей: эта функция [доступна с Pro](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection), проект остаётся на Free. Две информационные записи RLS Enabled No Policy относятся к серверным таблицам токенов, которые намеренно недоступны клиенту: [пояснение Supabase](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy).

## Теги

Вещи и покупки поддерживают несколько тегов: «От отца», «Повседневное», «Для особых случаев», «Светлое», «Тёмное», «Цветное», «Любимое», «База», «Акцент». Для готовых образов доступны «Лёгкий» и «Тёплый». Тег «Любимое» независим от отметки избранного. Теги выбираются в редакторе, видны на карточках, участвуют в поиске и фильтрах. Несколько выбранных фильтров означают наличие всех тегов. Сезоны убраны из интерфейса; прежние значения сохраняются в данных.

Теги хранятся в `wardrobe_entries.tags` в Supabase и включаются в ZIP-экспорт. Список вариантов задаётся в `src/domain.js`; расширение списка не требует изменения структуры таблиц. Старый клиент, не передающий `tags` при сохранении, сохраняет уже назначенные теги.
