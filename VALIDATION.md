# Проверка первой версии

## Выполнено локально

- `npm run build`: успешная сборка.
- `npm test`: 12 проверок, включая выполнение схемы в PGlite (PostgreSQL), RLS для анонимного и чужого пользователя, единственного владельца, транзакционное сохранение, неправильный путь фото и связи образов.
- Проверки Edge Functions с имитацией Supabase: неверный логин, расходование одноразового токена, отказ повторному запросу, запрет повторного создания аккаунта.
- Chromium 143, Playwright: 11 сценариев интерфейса. Вход, пустое состояние, мобильное меню и отсутствие горизонтального переполнения, загрузка фотографии и сохранение, редактирование, избранное, поиск и сброс, выбор вещей и переход к исходной карточке, перенос покупки, корзина и восстановление, ZIP-экспорт с фото, выход. Ошибок JavaScript не обнаружено.
- Визуально просмотрены экраны 1440 × 1000 и 390 × 844; исправлено расположение поля поиска.

## Подключённый Supabase

- Применены миграции в отдельном проекте `wardrobe`; существующий `monitoring-schedule` не изменялся.
- Все шесть таблиц имеют RLS. Bucket `wardrobe` закрыт. Клиентские роли не могут читать и создавать служебные токены.
- Развёрнуты `wardrobe-login`, `wardrobe-setup`, `wardrobe-agent` с собственной проверкой доступа.
- Supabase advisors: предупреждений безопасности нет; две информационные записи относятся к намеренно закрытым серверным таблицам токенов. Лишние права на dashboard-функцию автоматического RLS отозваны.
- В публичной конфигурации используется publishable key; секретные ключи отсутствуют.
- Auth API подтвердил `disable_signup: true` и `anonymous_users: false`: оба вида открытой регистрации выключены.
- Реальные HTTP-проверки: анонимное чтение каталога, запрос к фотографиям помощника без билета, настройка без билета и с недействительным билетом возвращают HTTP 401. Запрос OPTIONS для браузерного входа возвращает 204 с нужными CORS-заголовками.
- SQL-проверка под authenticated с чужим UUID не видит карточек. Дополнительная учётная запись для проверки не создавалась.

## Границы проверки

Проверка браузера использовала имитацию сетевых ответов. Реальный вход, сохранение фото и экспорт будут проверены после создания единственного личного аккаунта владельцем. Дополнительные QA-аккаунты в этом проекте не создавались.

Данные в интерфейсных испытаниях — только тестовые, не вещи пользователя. Фотографии пользователя не получены и никуда не опубликованы.
